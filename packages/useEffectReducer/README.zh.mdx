`useEffectReducer` 主要受 [Elm The Elm Architecture](https://guide.elm-lang.org/architecture/) 启发：`update : Model -> Msg -> ( Model, Cmd Msg )` 这种「状态 + 事件 = 新状态 + 副作用描述」的模式能让 reducer 保持纯净，同时显式声明副作用。我们把这套范式带回 React Hook 世界：reducer 仍是纯函数，但除了新状态，还能返回副作用描述，执行细节交给 hook 的解释器。

## 它解决了哪些问题？

- **副作用触发不再依赖“监听 state”**：reducer 直接返回 `[state, effect]`，副作用是事件驱动而非基于状态变化的“猜测”。
- **副作用具备生命周期与可取消性**：通过 `ctx.run(id, callback)` 和 `ctx.cancel(id)` 自动管理 `AbortController`，组件卸载或新的同名任务出现时自动 abort。
- **逻辑集中、易测试**：reducer 依旧纯净，可以 snapshot；`onEffect` 是唯一执行副作用的位置，可复用/集中 mock。
- **渐进式迁移**：API 与 `useReducer` 兼容，支持 `init`/延迟初始化等模式。

## API 概览

```ts
const [state, dispatch] = useEffectReducer(reducer, onEffect, initialState)
```

- `reducer(prevState, action) => [nextState, effect?]`
- `onEffect(effect, ctx)` 负责解释 effect，`ctx` 提供：
  - `dispatch`：继续发事件
  - `getState()`：读取最新 state
  - `abort`：当前 effect 根 AbortSignal
  - `run(id, runner)`：注册可自动取消的异步任务
  - `cancel(id)`：手动取消 `run` 注册的任务
